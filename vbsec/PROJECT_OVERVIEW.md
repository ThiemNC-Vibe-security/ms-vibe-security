# PROJECT OVERVIEW

## Project Title

Automatic Security Test Generation and Execution Framework for Web Applications using LLM and Playwright

---

# 1. Introduction

Modern AI-assisted development platforms enable developers to rapidly build web applications through Vibe Coding and Large Language Models (LLMs).

Although application development becomes significantly faster, security validation remains largely manual and requires security expertise.

This project proposes an automated framework capable of:

* Discovering web application structures and workflows.
* Collecting security-relevant application information.
* Combining application context with security knowledge.
* Generating security test scripts automatically using LLMs.
* Executing generated tests using Playwright.
* Producing security assessment reports with evidence.

The framework aims to reduce manual security testing effort while improving testing coverage for modern web applications.

---

# 2. Objectives

The project aims to:

1. Automatically discover target web applications.
2. Build a structured representation of application functionality.
3. Create a Security Testing Context (STC).
4. Generate Security Test Scripts (STS) using LLMs.
5. Execute generated tests using Playwright.
6. Collect execution evidence.
7. Generate security assessment reports.

---

# 3. Scope

## Included

* Traditional web applications.
* HTML/CSS/JavaScript-based systems.
* Black-box security testing.
* Automated test generation.
* Automated test execution.
* Automated reporting.

## Security Focus

The framework focuses on common web security vulnerabilities based on:

* OWASP Top 10
* OWASP ASVS
* CWE
* Security Test Patterns
* Emerging Web Security Risks (2025–2026)

## Excluded

* Mobile applications.
* Desktop applications.
* Source-code security review.
* Infrastructure penetration testing.

# 5. Core Components

## 5.1 Discovery Engine

Purpose:

Automatically explore the target application and collect information required for security testing.

Possible technologies:

* Browser-use
* Playwright Crawl
* Custom Playwright Discovery

Responsibilities:

* Discover pages.
* Discover forms.
* Discover inputs.
* Discover buttons.
* Discover navigation paths.
* Discover user workflows.
* Capture application metadata.

Output:

```json
{
  "pages": [],
  "forms": [],
  "inputs": [],
  "workflows": []
}
```

---

## 5.2 Security Knowledge Base

Provides security knowledge used during test generation.

Sources:

* OWASP Top 10
* OWASP ASVS
* CWE
* Security Rules
* Security Test Patterns

Purpose:

Map discovered application features to relevant security tests.

---

## 5.3 Tester Requirements

Tester Requirements provide human-defined constraints and testing objectives.

Example inputs:

### Target Information

* Target URL
* Environment (Dev/UAT/Production)

### Authentication

* Test Accounts
* Roles (Admin/User/Guest)

### Testing Scope

* Full Website
* Specific Modules
* Include URLs
* Exclude URLs

### Security Testing Types

* SQL Injection
* XSS
* Authentication Testing
* Authorization Testing
* OWASP Top 10 Assessment
* Full Security Assessment

### Testing Constraints

* No Data Deletion
* No Data Modification
* Read-Only Testing

### Additional Requirements

* Priority Features
* Report Format
* Custom Security Rules

Purpose:

Allow testers to guide and constrain automated testing.

---

## 5.4 Security Testing Context (STC)

The Security Testing Context is the central concept of the framework.

STC combines:

1. Application Context
2. Security Knowledge
3. Tester Requirements

```text
STC
├── Application Context
├── Security Knowledge
└── Tester Requirements
```

Purpose:

Provide a structured and standardized input for LLM-based security test generation.

---

## 5.5 LLM Test Generator

The LLM receives the Security Testing Context and generates Security Test Scripts.

Possible models:

* Gemini
* GPT
* Claude
* Open-source LLMs

Output:

Playwright-based Security Test Scripts (STS).

---

## 5.6 Security Test Scripts (STS)

STS are executable Playwright scripts generated by the LLM.

Responsibilities:

* Execute security test scenarios.
* Validate security controls.
* Detect potential vulnerabilities.

Examples:

* SQL Injection
* XSS
* Authentication Bypass
* IDOR
* Session Management Tests

---

## 5.7 Playwright Runner

Executes generated Security Test Scripts.

Responsibilities:

* Run tests.
* Collect screenshots.
* Collect logs.
* Capture traces.
* Store execution results.

Outputs:

* Pass/Fail Results
* Screenshots
* Logs
* Evidence

---

## 5.8 Report Engine

Aggregates execution results and generates security reports.

Report Contents:

* Executive Summary
* Findings
* Severity
* Evidence
* Reproduction Steps
* Recommendations

Supported Formats:

* HTML
* JSON
* PDF
